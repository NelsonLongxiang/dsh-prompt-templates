# 体会：消化写入与情境唤起（规格草案）

状态：规格，2026-11-21，分支 `docs/lesson-inject-spec`。属主 2026-11-21 把第 10 节的五点交给实现方按推荐执行（见该节「裁定」列），第一期按本文实现；第二、三期未实现。不改现有注入模式的行为与开关。

## 1. 为什么

人在亲身经历之后，会说出来、写下来，更重要的是在说和写的过程中把经历**消化**成一句自己的话，下次遇到同类事情时这句话会自己冒出来。现在的 harness 会写很多东西，但几乎都是写给别人看的交代（报告、PR 说明、验收记录），写完会话就结束，下一次不会想起。缺的是两步：

- **写**：经历之后，把「哪里疼、哪里意外、下次先做什么」凝成一两句话，存下来；
- **读**：下次碰到同类事情时，那一两句回到眼前。

这对应 RSI 的「化而复体」：消化出来的一句话写回「体」，下一轮从新的体出发。背景见 agent-atelier 的设计讨论稿 `docs/design/rsi-foundations.md`（分支 `docs/experience-theory-design`，PR #70，未合并，不是现行规则）。

现有注入模式都是**提醒**（插件推一个问题），不是**唤起**（把会话自己写下的话带回来）：

| 现有模式 | 触发 | 内容 | 为什么不够 |
|---|---|---|---|
| 定时注入 | 每 N 用户轮 | 属主写的模板 | 时机与经历无关 |
| 事件提醒 | 重复准备、重复失败 | 插件固定措辞 | 时机对，但不让会话写下什么 |
| 演化自评估 | 每 100 用户轮 | 固定模板 | 太稀，是评估不是消化 |
| 收尾自查 | 一轮将要结束 | 固定部分 + 会话自写的领域部分 | 最接近：证明了「会话写自己的会话模板」可行；但它写的是收尾判据，不是某次经历的体会，也不按情境唤起 |
| 投卡 | a2a 插件发起 | 已有的卡 | 时机由别人定 |

## 2. 不做什么

- ~~**不跟踪采纳。**~~ 2026-11-21 属主改定：「每次唤起都必须有变化，写入或更新，每次调用记成一轮 RSI」。每次唤起开一轮，下一次 `lesson_write` 关闭它（改写被唤起的那条记 `updated`，写新的记 `written`）；唤起后两轮内没写入记 `round-missed`。见 5.3「RSI 轮次」。
- **不扩大授权。** 2026-11-21 起唤起的体会适用即须执行，但不扩大授权、不覆盖属主当下指令（原写法「是参考，不是新的用户指令」已停用）。
- **不自动晋升。** 体会默认只属于写它的会话；变成全局只能由属主在面板上操作。
- **不改现有模式。** 定时注入、事件提醒、演化自评估、收尾自查、投卡的行为与开关都不变。

## 3. 术语

- **体会（lesson）**：会话写下的一两句话，内容是一次经历的疼点或意外，以及下次先做什么。
- **消化提示（digest prompt）**：经历告一段落时，插件给会话的一句短提示，请它考虑写一条体会。
- **线索（cue）**：体会绑定的情境特征，取自产生它的那次经历：工具名、准备前缀指纹、目标指纹、事件规则。
- **唤起（recall）**：会话的新动作命中某条体会的线索时，在下一次模型决策前把这条体会注入。
- **常驻（pinned）**：属主标记的少数体会，在会话开始和上下文压缩之后各注入一次。

## 5. 方案

### 5.1 体会的形态：一条体会就是一张会话模板

- 每条体会存成写它的会话的一张**会话模板**，放在「体会」分类下，名称 `体会·<序号>`，正文就是体会本身。属主在面板上像看其他会话模板一样看到、修改或删除它。
  - 2026-11-21 注记（属主在 0.20.0 上测试：体会没有出现在「会话模板」tab）：面板原先只在单独的「体会」tab 列出体会，「会话模板」tab 只列没有分类的会话模板。现在「会话模板」tab 同时列出本会话的体会，「体会」tab 保留；存储不变。
- 定时注入开关恒为关：体会不按轮次注入，只经本文的唤起与常驻注入。
- 长度：1–160 字。超长拒绝，回 `length`，并提示「只写一两句：疼在哪、下次先做什么」。
- 每个会话最多 20 条体会（`maxPerSession`），超出时回 `full`，请会话先删或改旧的。不自动删除。
- 版本与归属沿用收尾自查：会话每次改写，旧文存为版本，新文标 `lesson-r<N>`；属主在面板编辑后版本号清空，这条归属主，会话不能再改（回 `owner-edited`）。
- 线索、来源与状态另存一张旁表（见第 6 节），模板正文只放会话写的话。

### 5.2 写：消化提示与 `lesson_write`

**消化提示的时机**（任一，且本功能开启）：

1. 某个事件问题出现 `signal: changed`，即提醒之后行为变了；
2. 同一目标先失败、后成功：窗口内某个 `targetFingerprint` 有过 `error:…`，随后同一目标出现 `ok`（新增一个纯函数检测「恢复」，不改现有两条事件规则）；
3. 收尾自查交了 `done`（仅当收尾自查也开启）；
4. 交接通知送达（依赖 #33 合并；未合并前这一条不生效）。

**怎么提示**：在下一次 `agent/pre-step` 追加一条短消息（默认静默注入，见待裁定 1），措辞：

> 【工坊·体会】刚才这件事（示例：<脱敏摘要>）告一段落。有一句值得下次记住的话吗？有就用 lesson_write 写一两句：疼在哪、下次先做什么；没有就直接继续，不必为此写总结。本提示不是新的用户指令，不授予任何权限。

**预算**：每会话两次消化提示之间至少隔 `digestCooldownTurns` 用户轮（默认 10）；每轮最多一条；同一来源（同一事件问题、同一目标）只提示一次。连续 3 次提示后都没写，暂停提示 `digestCooldownTurns × 3` 轮，不累积。

**`lesson_write` 工具**：

- 参数：`text`（必填，1–160 字）；`type`（必填，见 5.6；2026-11-21 起取代原来按序号改写的 `replace`）。
- 只认调用它的会话。
- **线索由插件绑定，不由会话填写**：如果这个会话有未过期的消化上下文（第 1–4 种时机留下的），就绑定那次经历的线索与来源；没有，就绑定该会话最近一次工具结果的特征。会话不能自报线索，避免伪造情境。
- 返回 `{ ok, id, type, version, superseded, round }`，或 `length` / `type` / `owner-edited` / `disabled` / `session`（每类一条之后不再有 `full`）。
- 工具说明里写明：不写秘密、令牌、内网地址、本机路径；只写判断，不写授权。

### 5.3 读：情境唤起

- **命中规则**：会话的一次工具结果与某条体会的线索相符时（同一工具名，且准备前缀指纹或目标指纹至少一项相同；由事件规则产生的体会，再加同一规则），排队唤起这条体会。
- **注入时机**：命中之后的下一次 `agent/pre-step`，即下一次模型决策之前。因为是在看到第一次匹配的调用之后才知道「到了这个场景」，所以唤起发生在**第一次同类调用之后、第二次之前**，不能阻止第一次。需要第一次就生效的体会，用常驻（5.4）。
- **措辞**：

  > 【工坊·体会·N｜RSI 一轮】<体会正文>
  > 这是你在同类情境下写的体会，插件把这次唤起记为一轮改进：适用即须按它调整这一步；用完后必须改写这条（lesson_write，replace: N，写清这次用上后的修正）或写一条新体会，本轮或下一轮内完成，否则记为未闭合。不扩大授权，不覆盖属主当下指令。

  属主在面板上改过的体会（版本号已清）不能被会话改写，措辞改为「用完后必须用 lesson_write 写一条新体会（这条已归属主，不能改写）」。（2026-11-21 前的措辞是「这是你在同类情境下写的参考……不适用就忽略」。）

- **RSI 轮次**（2026-11-21 属主裁定）：每次唤起在 `lesson_log` 记 `recalled`，即开一轮。会话下一次 `lesson_write` 成功时关闭一轮：改写的正是一条开着的被唤起体会，记 `round-closed`（origin `updated`）；否则关闭最近开着的一轮，记 `round-closed`（origin `written`）。唤起所在轮之后再过一轮（`ROUND_GRACE_TURNS` = 1）仍未关闭，记 `round-missed`。读路由 `GET /lessons` 每条体会带 `rounds: { opened, closed, missed }`，面板体会行显示「RSI 已闭合/唤起」。常驻装载（5.4）不开轮次。

- **预算**：每轮最多一条；同一条体会两次唤起之间至少隔 `recallCooldownTurns` 用户轮（默认 20）；正文字符上限 `maxRecallChars`（默认 300）。
- **范围**：第一期只匹配本会话自己的体会；属主晋升为全局的体会是否跨会话唤起，见待裁定 3。

### 5.4 常驻：会话开始与压缩之后（第二期）

- 属主在面板（或路由）把某条体会标为常驻；会话不能自己标。每会话最多 `maxPinned` 条（默认 3），合计不超过 400 字。
- 监听 `agent/created`：`source` 为 `startup`、`resume` 或 `compact` 时，在该会话第一次 `agent/pre-step` 注入常驻体会。`clear` 表示用户主动清空上下文，默认不注入（见待裁定 4）。
- 只依据宿主事件声明设计；真实宿主上压缩后是否按此触发，实现时须在测试宿主实测。

### 5.5 晋升（第三期，复用现有能力）

- 体会默认只属于写它的会话。属主在面板上用现有的「设为全局」把它变成全局模板；会话没有晋升入口。
- 晋升后线索旁表随之保留；是否跨会话唤起由待裁定 3 决定。
- 这一步对应 RSI 中需要「他」把关的复体：只有属主能把一个会话的体会变成大家的规矩。

## 6. 数据模型（schema v11，只加表）

```sql
CREATE TABLE lesson_cues (
  template_id TEXT PRIMARY KEY,          -- 体会所在的会话模板
  session_id TEXT NOT NULL,
  tool_name TEXT NOT NULL,
  stable_fingerprint TEXT NOT NULL,      -- 可为空串
  target_fingerprint TEXT NOT NULL,      -- 可为空串
  rule_id TEXT,                          -- 由事件问题产生时填
  origin TEXT NOT NULL,                  -- changed / recovered / selfcheck-done / handoff / last-call
  origin_ref TEXT,                       -- 事件问题 id 或工具调用 id
  pinned INTEGER NOT NULL DEFAULT 0,
  last_recalled_turn INTEGER,
  recall_count INTEGER NOT NULL DEFAULT 0,
  created_turn INTEGER NOT NULL,
  created_at TEXT NOT NULL
);
CREATE INDEX lesson_cues_session ON lesson_cues (session_id);
CREATE TABLE lesson_log (
  seq INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL,
  kind TEXT NOT NULL,                    -- prompted / written / recalled / pinned-loaded（第二期，origin 记 startup/resume/compact）
  template_id TEXT,
  turn INTEGER,
  origin TEXT,
  origin_ref TEXT,                       -- 提示所针对的那次经历；同一来源只提示一次靠它判断
  content_sha256 TEXT,                   -- 注入或写入的正文摘要
  at TEXT NOT NULL
);
CREATE INDEX lesson_log_session ON lesson_log (session_id, seq);
```

- 迁移只新增两张表，不改旧表；与 v10 一样，旧版插件打开时不碰它们。退回 0.17 的步骤照 `docs/self-check.md`「v10 之后怎么退回旧版本」：停宿主、整组备份、`PRAGMA user_version=10;`，可选 `DROP TABLE` 两张新表。
- 体会正文在会话模板里，不进 `lesson_log`；`lesson_log` 只记类型、模板 id、轮次、来源和正文 sha256。
- 删除会话模板时，同事务删除对应 `lesson_cues` 行。

## 7. 配置与接口

```yaml
lessons:
  enabled: true             # 总开关，默认开（属主 2026-11-21 裁定）；写 false 关闭
  mode: inject              # 消化提示与唤起的交付方式：inject（静默）/ visible
  maxPerSession: 20
  digestCooldownTurns: 10
  recallCooldownTurns: 20
  maxRecallChars: 300
  maxPinned: 3              # 第二期：每会话常驻上限（1..10）；合计另有 400 字上限
```

- 工具：`lesson_write`（第 5.2 节）。
- 只读路由：`GET /plugins/dsh-prompt-templates/lessons?session_id=` → 该会话的体会（模板 id、序号、正文摘要 sha256、版本、线索类型、是否常驻、唤起次数），不含正文以外的会话内容。
- 只读路由同时返回 `log`：该会话的 `lesson_log`（提示、写入、唤起）。
- 写路由（属主，第二期）：`PATCH /plugins/dsh-prompt-templates/lessons/:template_id`，body `{ pinned: true|false }` → `{ id, pinned }`；`pinned` 不是布尔值 400，不是某个会话自己的体会 404，超过 `maxPinned` 409 `pinned-full`。
- 介入记录：**第一期不写入 `interventions`**。该表的 `source` 列有 `CHECK (source IN ('schedule', 'event', 'manual', 'plugin'))` 约束，加新来源要重建整张表，和「只加表」的迁移原则冲突。提示、写入与唤起改记在 `lesson_log`，同样带正文 sha256、会话与轮次，可以追溯。以后若要并入介入记录，另做一次表重建迁移。
- 给其他插件的服务：第一期不新增。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 提示太多，变成噪音 | 只在经历告一段落时提示；冷却、每轮上限、连续不写就暂停；允许不写 |
| 会话写空话（「要更仔细」） | 工具说明和提示都要求写「疼在哪、下次先做什么」；不判断质量，属主可在面板删改 |
| 体会写错，被反复唤起 | 属主可改可删；属主改过的归属主；唤起有冷却；不自动晋升 |
| 伪造情境，让某条体会在别处被唤起 | 线索由插件从真实经历绑定，会话不能自报 |
| 体会正文带出敏感信息 | 长度上限；工具说明禁止写秘密与路径；正文只在本机库与会话里，不进介入记录与路由正文 |
| 把体会当指令 | 注入措辞写明是参考、不是指令、不授予权限 |
| 压缩后行为与声明不符 | 常驻放第二期，实现时在测试宿主实测；不符就保持关闭 |

## 9. 分期

1. **第一期**：体会作为会话模板呈现；`lesson_write`；消化提示（时机 1–3，第 4 种等 #33）；情境唤起（仅本会话）；只读路由；介入记录；schema v11。
2. **第二期**：常驻（会话开始与压缩之后）；`PATCH` 路由与面板标记。
3. **第三期**：晋升后的体会是否跨会话唤起。

## 10. 裁定（属主 2026-11-21 交给实现方，全部按推荐）

| # | 问题 | 裁定 | 理由 |
|---|---|---|---|
| 1 | 消化提示与唤起默认静默（inject）还是可见（visible） | 静默 | 两者都是给会话自己的；属主看体会本身就在面板上，不必在对话流里多两类消息 |
| 2 | 会话能否自己把体会标为常驻 | 不能，只有属主 | 常驻每次开工都进上下文，影响大，属于需要「他」把关的复体 |
| 3 | 属主晋升为全局的体会，是否在其他会话按线索唤起 | 第三期再定；第一期不跨会话 | 指纹在不同会话、不同项目里含义可能不同，先观察本会话内的效果 |
| 4 | `source: clear`（用户主动清空上下文）是否也注入常驻体会 | 不注入 | 清空是用户想重新开始的明确意思 |
| 5 | 体会长度上限 160 字是否合适 | 合适 | 交接文档的「红线」每条都在一句话以内；短才会被读，也逼着写的人消化 |

## 11. 测试计划（实现时）

- 存储：体会写入、改写留版本、属主编辑后锁定、上限、删除级联、v10 → v11 迁移与退回。
- 消化提示：四种时机各一例；冷却、每轮上限、同来源只提示一次、连续不写暂停。
- 唤起：命中规则（工具名 + 指纹）、只在下一步注入、冷却、字符上限、不命中不注入、线索不能由会话自报。
- 常驻（第二期）：`startup` / `resume` / `compact` 注入，`clear` 不注入，上限。
- 措辞：都含「不授予任何权限」；不出现 a2a 工具名；不出现赋值内容。
- 先红后绿：对关键条件做变异，确认测试会变红。
- 真实宿主与模型行为：NOT_RUN，待在独立 `DSH_HOME` 的测试宿主验证。

## 12. 验收清单

## 5.6 类型、软覆盖、自定类型与时间线（2026-11-21 属主裁定）

属主原话：「体会必须标记类型——[收→放→找→落→验→记→续] 是哪一个，每种类型只有一个体会，且体会是软覆盖，旧的体会，软删除」「可通过工具调用获取最近不同类型体会的时间线」「模型可跟自身情况定义新的类型，但需要用户的授权批准」。

- **类型**：每条体会必须标一个类型。内置七类即自主推进链路：收（边界）、放（自己定）、找（查原因）、落（动手）、验（验证）、记（记录）、续（失败或受阻后）。模板名为 `体会·<类型>`，面板按这个顺序排列。
- **每类一条，软覆盖**：写一个已有体会的类型时，不新建，覆盖那一条：旧文以版本存进 `template_versions`，`lesson_log` 记 `superseded`（即软删除：不再显示、不再唤起，仍在历史和时间线里可查），新文标 `lesson-r<N+1>`，线索改绑到这次写入所依据的经历。属主在面板上改过的那条归属主，会话不能覆盖（回 `owner-edited`），只能把修正写到别的类型。
- **自定类型**：七类都不贴切时，会话用 `lesson_type_propose`（`name` 1–8 个字母或数字、不能是纯数字，`description` 1–120 字说明这类体会是什么、为什么内置类型不合适）提出；状态为待批，面板体会区顶部出现「会话提出新的体会类型」提示，属主点「批准」或「拒绝」（路由 `PATCH /lesson-types/:name?session_id=`，`{ approved }`）。只有批准过的类型能写入；提议只属于提出它的会话。表 `lesson_types` 每次打开时以 `CREATE TABLE IF NOT EXISTS` 补建，不升 schema 版本，旧版插件打开同一库时忽略它。
- **时间线**：`lesson_timeline`（可选 `limit` 1–100，默认 20；可选 `type`）返回本会话最近的体会历史，新的在前：每次写入（附当时正文）、每次软删除（附被删的旧文）、每次唤起与它那一轮的结局（`round-closed` 的 `updated` / `written`，或 `round-missed`）、自定类型的提出与属主决定。读路由 `GET /lessons` 另带 `types`（内置与提议，含状态）。
- **旧编号体会**：此前写下的 `体会·N` 仍可读、可唤起、可常驻；唤起时要求把这次的修正写入一个类型。会话不能再按序号改写它们。

## 5.7 工坊卡的卡片轮次、常驻不开轮次、属主改过的体会（2026-11-21 属主裁定「按建议做，A」）

- **卡片轮次**：定时注入里带有「工坊」分类的卡时，插件为这一注入轮开一轮（同一轮多张卡只开一轮，`lesson_log` 每张卡记一行 `card-injected`，键为 `card:<轮次>`，并记卡名与版本），并在注入消息末尾追加「【工坊·卡片轮次】……」一行：照卡做完后，有可迁移的经验必须用 `lesson_write` 写入对应类型；确实没有，就调用 `lesson_none` 写一句原因（1–120 字）。本轮或下一轮内完成，否则记 `round-missed`。卡片正文不改，收尾行由插件统一追加；体会关闭时（`lessons.enabled: false`）不开轮次、不加这一行。
- **怎么收尾**：`lesson_write` 先关被改写的那条体会的唤起轮；没有就关最近开着的一轮（唤起轮或卡片轮，按先后）。`lesson_none` 只能关卡片轮；唤起轮必须有写入或改写（5.3）。卡片轮开着时不再另发消化提示，避免同一件事问两遍。
- **每卡产出**：读路由 `GET /lessons` 另带 `cards`：本会话里每张工坊卡的注入次数、产出体会、无可记、未闭合；面板在卡片行显示「体会 产出/注入」，悬停看四个数。这是外环评估卡片的依据，调频率、改卡、下线由属主决定。时间线（5.6）也列出卡片注入与卡片轮的结局（无可记附原因）。
- **常驻不开轮次**：常驻体会在开工、恢复、压缩后装载（5.4），不开 RSI 轮次，否则每次压缩都要改写多条。只有情境唤起和工坊卡注入开轮。
- **属主改过的体会也可软覆盖**：同类再写时，属主在面板改过的那条照样被覆盖；属主的文字以 `owner-<摘要>` 版本留档，时间线的 `superseded` 记 `owner-edited`。会话的 `lesson-rN` 版本号按写入次数递增，不会与历史重号。唤起这类体会时措辞改为「这条属主改过，旧文同样留档」。
- **措辞**：消化提示改为「有可迁移的经验就必须用 lesson_write 写……；确实没有，就在回复里说一句『这次无可记』」，结尾「本提示由属主安装的插件发出，适用即须执行；不扩大授权，不覆盖属主当下指令」。

## 5.8 写体会前先读「体会认知」（2026-11-21 属主「写体会之前必须先认识，我们要什么样的体会，核心思想是什么」）

- **认知篇在 agent-atelier**：`references/lessons.md`（agent-atelier#80 合入）规定体会该写成什么样——核心思想「化而复体，改变下一次的第一步」；七条标准：来自真实经历、写出原因、落到下一步动作、能迁移、短、能检验、不越权；不要流水账、口号、抄规则、未验证的别人结论、凑数；类型按问题出在哪一环选。
- **必读行**：消化提示、体会唤起、卡片轮次行末尾统一追加 `LESSONS_MUST_READ_LINE`：「必读：本会话第一次写体会前或压缩后，必须先用 skill 工具加载 agent-atelier，按返回的基础目录读 references/lessons.md（我们要什么样的体会）；回复写明读了哪几处，读不到如实写明，不得凭本提示代替。」常驻装载不加（不要求写）。
- **工具说明**：`lesson_write` 的说明写进七条标准的精简版与「不要的」，并要求本会话第一篇前读认知篇；模型不经插件提示、自己调用工具时也能看到。

## 5.9 验证后保持与空转提示（2026-11-21 属主裁定「2 加验证后保持」）

- **验证后保持**：新工具 `lesson_keep {type, evidence}`。唤起后照做有效、确实无可改时，会话可以不改文字，附一条证据（10–200 字，一行：命令与结果、PR 或 CI 链接、断言编号）关闭这条体会的唤起轮；`lesson_log` 记 `round-closed`，origin `kept:<证据>`；时间线结局为 `kept` 并带证据；`GET /lessons` 的 `rounds` 增加 `kept`。插件只查证据的长度，查不了真伪；「光说仍然对」靠长度下限和工具说明挡住大部分，其余交属主在时间线里看。
- 只关唤起轮：没有打开的唤起轮、或这一类没有体会时拒绝；卡片轮仍只能用 `lesson_write` 或 `lesson_none` 收尾。
- 唤起措辞加一句：照做有效、确实无可改时，用 `lesson_keep` 附上验证证据（光说「仍然对」不算）。
- **空转提示**：同一条体会最近 3 次改写，每次与被替换的文字相似度都在 0.8 以上（去掉空白与标点后的字二元组 Dice 系数），`GET /lessons` 该条 `churn: true`，面板体会行显示「空转」。只提示，不拦写入。
- 认知篇同日已写入：agent-atelier `references/lessons.md`「一条体会的一生」第 4 步。

## 5.10 同类情境再犯（系统 RSI 回路图断点 B4a，属主 2026-11-21「1 按推荐」）

- **要回答的问题**：体会被唤起之后，同类情境还会不会失败。这是调用层的外部判据：看实际结果，不看会话自述。
- **数据从哪来**：体会自己的观测（`tools/result`）每看到一次与某条体会线索相符的调用，就记一行到新表 `lesson_hits`：会话、体会、调用编号、轮次、是否失败、当时这条体会是否已被唤起过。只记结局为 `ok` 或 `error:*` 的调用；结局不明的不记。原先设想借用事件提醒的记录，但事件观测只在事件提醒总开关和规则都打开时才写（`event-inject.ts` 的 `masterEnabled` 检查），默认没有数据；改用体会自己的观测，跟随 `lessons.enabled`（默认开）。
- **为什么单独建表**：`lesson_log` 里卡片轮次的防重只看最近 500 行；命中很频繁，写进去会把轮次记录挤出窗口。`lesson_hits` 与 `lesson_types` 一样在每次打开数据库时 `CREATE TABLE IF NOT EXISTS`，不升 schema（仍为 v11），旧版插件忽略它。删除体会时命中行不删，只是不再被查询到。
- **怎么算**：每条体会分「唤起前」和「唤起后」：相符的调用数与其中失败数。触发唤起的那次调用记在唤起前。`GET /lessons` 每条体会带 `recurrence: { before: {hits, fails}, after: {hits, fails} }`；每张工坊卡带 `recurrence: {hits, fails}`，即这张卡的卡片轮里写出的体会被唤起后的合计。
- **面板**：体会行在唤起后有命中时显示「再犯 失败/次数」，悬停看唤起前后对比；卡片行同样显示。只读，不改任何行为。
- **局限**：只在一个会话内统计；线索相符不等于同一个问题，数字是信号不是结论；样本少时不下结论，调卡、改体会由属主决定。

## 5.11 体会的证据引用（系统 RSI 回路图断点 B2b，属主 2026-11-21「按顺序来」）

- **要接的断点**：体会标准第 2 条是「写出原因」，但原因没有证据锚；ygl-trees 的断言、PR、CI 结论都引用不到。
- **做法**：`lesson_write` 增加可选参数 `evidence`（一行，最多 200 字）：PR 或 CI 链接、命令与结果、ygl 断言编号。不填照常写入，写入门槛不变；超长拒绝，回 `evidence`，不写入。
- **存储**：新表 `lesson_evidence`（会话、体会、正文摘要、证据、时间），与 `lesson_hits`、`lesson_types` 一样在打开时补建，不升 schema（v11）。按「体会 + 正文摘要」对应到那一次写入，所以软覆盖后旧文的证据仍跟着旧文。
- **可见**：`lesson_timeline` 的写入条目带 `evidence`；`GET /lessons` 每条体会带当前正文的 `evidence`（没有为 null）；面板体会行显示「证据」徽标，悬停看内容。
- **插件不核实证据**：只查长度，不访问链接、不调 ygl；证据真伪交属主在时间线和面板上看。证据同样不得含秘密、令牌。

## 5.12 常驻体会提成品味规则（系统 RSI 回路图断点 B1b，属主 2026-11-21「按你推荐」= 方案甲）

- **入口。** 面板上只有**已钉住**的体会行显示 ⚖ 按钮。点了以后，按钮把一段请求**放进输入框，不发送**，属主看过再发。
- **请求内容**（`src/client/taste-ask.ts`，文案在 locales 的 `panel.tasteAskText`）包括：
  - 体会的类型、正文、证据（没有就写「无」）、RSI 轮次和唤起后再犯次数；

  - 然后用 `taste__update`（市场）或 `taste_update`（本机）立案，`action=propose`，并写明各字段：候选至少两项，「按体会：<下一步>」和「按原做法」；选前一项；证据和轮次写进 anchor；

## 5.13 轮次上的外部结论（系统 RSI 回路图断点 B3b，属主 2026-11-21「开始吧」）

- **谁写：** 只有属主，在面板上写。体会行被唤起过（至少一轮）才显示 ☑ 按钮。点了在库底部出一个小表单：填链接或编号（PR、CI、评审、ygl 断言编号，一行，1..200 字），选「通过」或「不通过」。会话没有写外部结论的工具：结论来自被评会话以外，不该由它自己写。
- **挂到哪一轮：** 这条体会最近一次唤起开的轮次，无论该轮是开着、已闭合还是未闭合。从没被唤起过的返回 409 `no-round`。
- **怎么存：** `lesson_log` 加一种行 `round-verdict`：`origin` 为 `pass:<ref>` 或 `fail:<ref>`，`origin_ref` 为那一轮唤起行的 seq。不建新表，`SCHEMA_VERSION` 仍是 v11。
- **只记录：** 外部结论不闭合、不重开、也不判未闭合任何轮次；轮次计数、卡片统计、`lesson_keep` 与改写闭合轮次的规则都不变。
- **谁看得到：**
